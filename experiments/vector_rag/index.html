二、五种检索方法原理

🔤 BM25 — 关键词精确匹配
查询分词 → TF-IDF 加权 → BM25 评分 → 排序

通过词频(TF)和逆文档频率(IDF)计算查询与文档的相关性。擅长精确关键词匹配，对中文分词+字符 n-gram 双通道处理。

🧠 BM25+KG — 图谱增强
查询 → 知识图谱匹配 → 扩展查询 → BM25

先用知识图谱扩展查询（如"密度计"→"浮力、密度、液体"），再用扩展后的查询做 BM25 检索。解决"用户说A，文档写B"的语义鸿沟。

📐 Vector — 向量语义检索
文本 → Embedding 模型 → 384维向量 → Cosine 排序

用 embedding 模型将文本编码为稠密向量，通过余弦相似度计算语义距离。擅长理解同义词和语义相近但字面不同的表达。

🔗 Vector+KG — 图谱增强向量
查询 → KG 扩展 → Embedding → Cosine

先用图谱扩展查询语义，再做向量检索。让 embedding 模型看到更完整的查询意图。

⚡ Hybrid — BM25+Vector RRF 融合
查询 → KG 扩展 → BM25 召回 + Vector 召回 → RRF 融合 → 排序

两路召回后用 Reciprocal Rank Fusion (RRF) 融合：score = Σ 1/(k+rank)，k=60。结合关键词精确匹配和语义理解的优势。

#1
BM25+KG
0.783 MRR
图谱扩展让 BM25 从 0.733 提升到 0.783（+7%）。在"密度计的工作原理"等间接查询上效果显著。
#2

纯关键词检索已很强。中文字符 n-gram 分词 + BM25 在精确匹配场景下表现优异。
#3
Hybrid
0.561 MRR
Hit@3=0.800 与 BM25+KG 持平，但 MRR 更低。RRF 融合有时把精确命中排到后面。
💡
为什么向量检索表现差？ 实验使用英文模型 bge-small-en-v1.5 处理中文字幕，语义理解能力不足。例如"浮力在潜水艇中的应用"在向量空间中找不到相关文档（MRR=0），但 BM25 通过关键词"潜水艇""浮力"精确命中（MRR=1.0）。

改进方向：使用中文 embedding 模型（如 bge-m3 或 bge-large-zh）会大幅提升向量检索效果。
🔑
图谱增强的价值：在 15 条测试查询中，KG 扩展帮助了 3 条查询从 0 分提升到有分。最典型的案例是"密度计的工作原理"——BM25 直接搜不到（MRR=0），但 KG 把"密度计"扩展为"浮力、密度、液体"后命中（MRR=0.5）。

这正是当前项目的核心差异化能力。

结论与建议

  • 当前生产方案：BM25 + 图谱增强（MRR=0.783），零外部依赖，延迟最低
  • 向量检索定位：作为 Hybrid 的补充，用中文模型后效果会大幅提升
  • 下一步：接入 bge-m3 中文模型 → 重跑实验 → 预期 Vector MRR 从 0.3 提升到 0.6+
  • 图谱扩展是核心差异化：无论哪种检索方法，KG 增强都能带来稳定提升
